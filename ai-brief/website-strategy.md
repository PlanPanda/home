# ข้อเสนอเว็บ Solid Plan — ฉบับหารือ

วันที่ 13 ตุลาคม 2569 สถานะ: ข้อเสนอเบื้องต้น ยังไม่ใช่ requirement ที่อนุมัติ

คำตอบรอบแรก: กลุ่มหลักคือตัวแทนรายบุคคลที่มีฐานลูกค้าแล้ว CTA หลักนัดดูเดโมหรือทัก LINE และ AI อ่านกรมธรรม์/เพิ่ม/ลบ/แก้ไขข้อมูลจะเปิดให้บริการเมื่อเว็บใหม่เปิด ข้อเสนอด้านล่างให้อ่านโดยใช้คำตอบนี้แทนสมมติฐานเดิม

ผลต่อ Home: นำด้วยงานรายบุคคลและเดโมกรมธรรม์ วางทีมเป็นเนื้อหารอง ใช้ CTA “นัดดูเดโมผ่าน LINE” เมื่อยืนยันช่องทางและกระบวนการนัดแล้ว ราคาและสมัครเองเป็นทางรอง ไม่ใช้ “ทดลองใช้ฟรี” เป็นคำหลักจนทราบเงื่อนไข

คำตอบรอบสองแทน CTA ข้างต้น: ใช้ “เพิ่มเพื่อนใน LINE” → https://line.me/R/ti/p/@675lurmh ทุกการบันทึก AI ต้องกดยืนยันก่อน วันสำคัญดูในปฏิทินบนเว็บ ยังไม่มีแจ้งเตือน

โครงสร้าง Home ฉบับปรับตามคำตอบ: Hero+เพิ่มเพื่อนใน LINE → เดโมอัปโหลด/ตรวจข้อมูล/ยืนยัน/เปิดหน้าลูกค้า → ค้นข้อมูลลูกค้าและกรมธรรม์ → ดูวันสำคัญและประวัติติดต่อ → วิธีเริ่มใช้ → ความปลอดภัยที่ตรวจสอบได้ → FAQ+เพิ่มเพื่อนใน LINE ราคาและคำรับรองเป็นส่วนรอข้อมูล ไม่เติมข้อเท็จจริงเอง

ข้อความในเดโม: ก่อนยืนยันใช้ “ข้อมูลที่อ่านได้” หรือ “พร้อมให้ตรวจสอบ” หลังยืนยันและบันทึกสำเร็จจึงใช้ “บันทึกแล้ว” ช่องที่อ่านไม่ได้แสดง “ไม่พบในเอกสาร” และไม่เดาค่า ข้อมูลสาธิตทุกกรณีระบุว่าเป็นข้อมูลสมมติ

หลักฐาน HTML การสร้างกรมธรรม์ที่ได้รับเพิ่มเติม: ผู้ใช้แนบ PDF เพื่อเพิ่มกรมธรรม์ให้ลูกค้าเดิม → การ์ดยืนยันแยกข้อมูลกรมธรรม์ การเงิน/วันสำคัญ ค่าเริ่มต้นระบบ และสัญญาเพิ่มเติม → “ยืนยันสร้าง” / “ยกเลิก” → สถานะรอยืนยัน ยังไม่มีผลบันทึกสำเร็จในตัวอย่าง

สำหรับ mockup ให้แสดงข้อมูลหลัก 4–6 ช่อง แล้วพับรายละเอียดสัญญาเพิ่มเติมและค่าเริ่มต้นในส่วนที่เปิดอ่านได้ ต้องยังมองเห็นว่ามีข้อมูลไม่ระบุและค่าเริ่มต้นก่อนกดยืนยัน ห้ามทำให้ข้อมูลไม่ครบดูเหมือนอ่านครบ ตัวอย่างที่ส่งมีขั้นตอนโหลดตัวเลือกไม่สำเร็จ จึงต้องขอหลักฐาน flow สำเร็จสำหรับวิดีโอ และใช้คำเตือนภาษาผู้ใช้แทนชื่อเครื่องมือภายในเมื่อออกแบบสื่อ

## หลักฐานและขอบเขต

ตรวจเว็บสด https://solidplan.ai/ ผ่านเบราว์เซอร์ อ่าน HTML ตัวอย่างและ screenshot ที่แนบ อ่านเอกสารราคา/แบรนด์/สรุปสำรวจใน repo และตรวจบางส่วนของ `smart/app/services/ai_chat_service.ts` ไม่ได้ทดสอบระบบจริงครบทุก flow

ตลาดประกันชีวิต: สมาคมประกันชีวิตไทยรายงานครึ่งแรกปี 2569 ช่องทางตัวแทนมีสัดส่วนเบี้ยรวม 48.23% และเบี้ยรับปีต่อไปเติบโต 6.94% การดูแลต่อเนื่องจึงเป็นบริบทที่เหมาะกับผลิตภัณฑ์ ทั้งนี้ตัวเลขไม่พิสูจน์ความต้องการซื้อ Solid Plan และไม่ครอบคลุมตลาดประกันวินาศภัย

แหล่งข้อมูล: https://www.tlaa.org/page_bx.php?cid=23&cno=2373 (เนื้อหารายงานวันที่ 31 กรกฎาคม 2569 หน้าเว็บแสดงวันโพสต์ 13 ตุลาคม 2569)

`research/survey.md` เป็นสรุปภายใน ไม่มีต้นฉบับ จำนวนผู้ตอบ วิธีคัดเลือก หรือวันที่สำรวจที่ตรวจสอบได้ ใช้ตั้งสมมติฐานเท่านั้น ไม่ใช้เปอร์เซ็นต์โฆษณาหรืออ้างแทนตัวแทนทั้งประเทศไทย

## การตลาดที่เสนอ

กลุ่มเริ่มต้นที่เสนอ: ตัวแทนประกันชีวิตรายบุคคลที่มีฐานลูกค้าและกรมธรรม์เดิมแล้ว งานซ้ำชัดและเห็นคุณค่าจากนำเข้าไฟล์ครั้งแรกได้ หัวหน้าทีมเป็นช่องทางแนะนำและกลุ่มรอง สมมติฐานนี้รอเจ้าของยืนยัน

ข้อความหลัก: “ผู้ช่วย AI สำหรับตัวแทนประกัน ที่ทำงานกับข้อมูลลูกค้าของคุณได้จริง”

ข้อความสนับสนุน: “รวมข้อมูลลูกค้า กรมธรรม์ และวันสำคัญไว้ในที่เดียว ให้ AI ช่วยบันทึก ค้นหา และเตรียมข้อมูลก่อนติดต่อลูกค้า” ใช้เฉพาะความสามารถที่เปิดใช้จริง

ตัวเลือกพาดหัว: “ลดงานกรอก เพิ่มเวลาดูแลลูกค้า” แล้วระบุ AI และงานประกันทันทีในคำอธิบาย ไม่รับประกันยอดขายหรือความถูกต้อง 100%

การแข่งขันที่ต้องพิสูจน์: กระบวนการใช้ AI ทั่วไปพร้อมไฟล์แนบ/แหล่งข้อมูล, LINE+folder+spreadsheet, เครื่องมือของบริษัทประกัน, CRM ทั่วไป ต้องเปรียบเทียบ workflow ไม่กล่าวว่า AI ทั่วไปไม่มี storage หรือสับสนเสมอ และไม่กล่าวว่า Solid Plan เป็นรายเดียวโดยไม่มีหลักฐาน

จุดขายที่ทดสอบได้: งานจากไฟล์ไปถึงข้อมูลลูกค้าที่ใช้งานต่อได้, ค้นข้อมูลเดิมพร้อมทางไปดูรายการ, รู้วันสำคัญและประวัติติดต่อในระบบเดียว

ช่องทางทดสอบ: เดโมในกลุ่ม/เวิร์กช็อปตัวแทน, หัวหน้าทีมแนะนำ, คลิปสั้นตาม pain พร้อม CTA เดียว ไม่สรุปว่าช่องทางใดดีที่สุดจนมีข้อมูล

ตัวชี้วัด: คลิก CTA → สมัคร → นำเข้า/สร้างข้อมูลลูกค้าสำเร็จครั้งแรก → ถามข้อมูลที่บันทึกไว้ → กลับมาใช้งาน → จ่ายเงิน แยกตามแหล่งที่มาและกลุ่มผู้ใช้ การเก็บตัวชี้วัดต้องไม่ส่งเนื้อหากรมธรรม์/ข้อมูลลูกค้าเข้า analytics

ทดสอบก่อนล็อกข้อความ: ให้ตัวแทนจริงดูเดโมสั้นแล้วอธิบายประโยชน์กลับ ถามเหตุผลที่ยังไม่สมัคร ความกังวลเรื่องข้อมูลและการย้ายข้อมูล วัดเวลางานเดิมเทียบงานใหม่ก่อนใช้คำอ้างเรื่องประหยัดเวลา

## สิ่งที่ควรแก้จากเว็บปัจจุบัน

- Hero “รายได้ที่ดี ... โชคช่วย” ยังไม่บอกงานที่ AI ช่วย เปลี่ยนเป็นผลลัพธ์เฉพาะงานและภาพผลิตภัณฑ์
- การ์ดเดิม CRM/วางแผน/ทีมยังไม่พิสูจน์ flow AI; ใช้สถานการณ์และผลลัพธ์จริงแทน
- ภาพบุคคลขนาดใหญ่ใน Hero แย่งพื้นที่พิสูจน์ผลิตภัณฑ์ เปลี่ยนจุดเด่นเป็น chat พร้อมข้อมูลลูกค้าหลังบันทึก
- คำรับรองที่เว็บแสดงทั้งหมดเป็นตัวแทน AIA ให้ระบุว่าเป็นผู้ใช้รายบุคคลและไม่มีความหมายเป็นการรับรองโดยบริษัท เสริมหลายสังกัดเมื่อมีหลักฐานและสิทธิ์เผยแพร่
- ไม่ใช้ตรา SOC/HIPAA แบบทำให้เข้าใจว่า Solid Plan ได้รับรองเอง และทบทวนข้อความ “ระดับเดียวกับสถาบันการเงิน”
- ราคาในเอกสารกับเว็บสดต่างกัน: Pro ใน brief สูงสุด 1,000 ลูกค้า แต่เว็บสด 2,000 ราย ต้องยืนยันราคา/โควตา/ค่า AI ก่อนทำใหม่
- เก็บหน้า security/privacy/contact และปรับเนื้อหาให้ตรงผลิตภัณฑ์ใหม่ ตรวจลิงก์ที่ปัจจุบันเป็น # และปี footer เมื่อทำเว็บจริง

## โครงสร้างที่เสนอ

Home: Hero+CTA → เดโมอัปโหลดกรมธรรม์ → ประโยชน์ 3 เรื่อง (ลดกรอก/ค้นเร็ว/ดูแลต่อเนื่อง) → ขั้นตอนเริ่มต้น → คำรับรองที่ตรวจได้ → ความปลอดภัยแบบมีแหล่งอ้างอิง → ราคาเบื้องต้น/ลิงก์ราคา → FAQ+CTA

Features: แบ่งตามงาน ได้แก่ นำเข้ากรมธรรม์และ AI, ข้อมูลลูกค้าและไฟล์, นัดหมายและวันสำคัญ, ประวัติติดต่อและติดตามงาน, ผลงานและทีม แต่ละส่วนมี pain → flow → ผลลัพธ์ → ข้อจำกัด/ลิงก์คู่มือ เฉพาะฟีเจอร์ที่ยืนยันแล้ว ไม่แสดง roadmap เหมือนเปิดใช้แล้ว

เมนู: หน้าแรก / ฟีเจอร์ / ราคา / ความปลอดภัย / คู่มือ / TH–EN / เข้าสู่ระบบ / CTA หลัก มี contact ใน footer และ CTA รอง

ไทยก่อน รองรับเส้นทางภาษาและชุดข้อความแยกกัน อังกฤษแปลหลังข้อความไทยลงตัว ไม่แสดงสวิตช์ EN ที่นำไปหน้าว่างหรือเนื้อหาไทย

แนวภาพ: ขาว ดำ เทา ลำดับข้อความชัด พื้นที่ว่างพอดี ภาพผลิตภัณฑ์เด่น เนื้อหายาว Sarabun ไม่ใช้การบีบตัวอักษรไทย ช่วงแรก SVG และ chat สาธิตเท่านั้น ใช้สีโลโก้ตาม asset จริงโดยรอข้อสรุปว่าต้องการข้อยกเว้นสีแบรนด์หรือไม่

Chat สาธิต: ปุ่มเลือก 3 สถานการณ์ บทสนทนากำหนดไว้ด้วย JavaScript กดเล่น/ย้อนเริ่มได้ ไม่เชื่อมฐานข้อมูลหรือรับไฟล์จริง ระบุ “ตัวอย่างการใช้งาน · ข้อมูลสมมติ” แสดงอ่านไฟล์ → สรุปข้อมูล/ช่องว่าง → การบันทึกตามโหมดจริง → ปุ่มไปดูหน้าลูกค้า ไม่โชว์เมนูและตัวเลือกทั้งหมดของแอป

ภาพแนบแสดงว่า AI แจ้งข้อมูลที่ขาดและค่าเริ่มต้นได้ นี่ควรเป็นส่วนหนึ่งของเดโม: แยกข้อมูลจากเอกสารกับค่าที่ระบบตั้ง ไม่เติมเลขกรมธรรม์/วัน/เบี้ยเองเพื่อให้ภาพสมบูรณ์

## วิดีโอที่ควรบันทึก

1. สำคัญที่สุด 45–90 วินาที: อัปโหลดกรมธรรม์ตัวอย่าง → AI อ่าน → ตรวจสิ่งที่ขาด → บันทึกตามขั้นตอนจริง → เปิดข้อมูลลูกค้าและกรมธรรม์ → ถามต่อจากข้อมูลเดิม
2. 20–40 วินาที: ถามข้อมูลลูกค้า → คำตอบ → เปิดรายการต้นทาง ถ้าระบบมีการเชื่อมไปต้นทางจริง
3. 20–40 วินาที: วันเกิด/วันชำระเบี้ย/นัดหมาย → เปิดลูกค้า → ประวัติติดต่อ แยก “แสดงในปฏิทิน” จาก “แจ้งเตือนออกนอกระบบ”
4. 20–40 วินาที: ค้นลูกค้าที่ไม่ได้ติดต่อ → อ่านประวัติ → เตรียมติดตาม แสดงเกณฑ์ที่ใช้จริง
5. 20–40 วินาที: แก้ข้อมูล → การยืนยัน/ยกเลิกตามโหมดจริง ไม่ใช้การลบลูกค้าเป็น Hero
6. Optional: หัวหน้าทีมดูภาพรวมและสิทธิ์เข้าถึง ใช้เมื่อกลุ่มเป้าหมายและฟีเจอร์ยืนยัน

ใช้ชุดข้อมูลสมมติเดียวกันทุกคลิปและไฟล์กรมธรรม์ตัวอย่างที่ไม่ใช้ข้อมูลจริง อัดจอ 16:9 อย่างน้อย 1080p จออ่านง่าย เคอร์เซอร์ไม่แกว่ง ปิด notification ไม่ต้องใส่เพลง/ซับ/ตัดต่อในต้นฉบับ อัด flow จบจริงรวมระยะเวลารอ แล้วค่อยตัดคลิปเว็บ 8–15 วินาที ถ้าเร่งความเร็วต้องระบุ อย่าใช้วิดีโอยาว autoplay หน้าแรก มี poster และปุ่มเล่นรองรับ reduced motion

## ความปลอดภัยและ claim

Railway Trust Center แสดงหัวข้อ SOC 2 Type 2, SOC 3 และ HIPAA: https://trust.railway.com/ ตรวจวันที่ 13 ตุลาคม 2569 ต้องตรวจขอบเขตเอกสาร/บริการและเงื่อนไขก่อนขยาย claim

ข้อความแนะนำ: “Solid Plan ใช้ Railway เป็นผู้ให้บริการโครงสร้างพื้นฐาน ซึ่งเผยแพร่ข้อมูลมาตรฐาน SOC 2 Type 2 ใน Railway Trust Center” พร้อมลิงก์ คำรับรองดังกล่าวเป็นของผู้ให้บริการ ไม่ได้ทำให้แอปได้รับมาตรฐานตามไปด้วย

ยังไม่ยืนยัน: การเข้ารหัสทุกชั้น, ที่ตั้งข้อมูล, backup/restore, retention, AI ไม่เก็บข้อมูล/ไม่ใช้ฝึกโมเดล, compliance ของแอป, สิทธิ์ส่งออกและลบข้อมูล ต้องตรวจการตั้งค่า ผู้ให้บริการ และนโยบายจริง

ใน code พบ server-side approval gate และการตั้งค่าที่เกี่ยวกับการเขียนข้อมูล แต่ยังไม่ได้ตรวจ flow แต่ละโหมดครบ จึงไม่ใช้ข้อความ “ทุกคำสั่งต้องยืนยัน” จาก HTML จนยืนยันพฤติกรรมจริง

## คำถามสำหรับรอบถัดไป

CTA และราคา/ทดลองใช้ฟรี; กลุ่มหลักและคำรับรองเผยแพร่ได้; ฟีเจอร์เปิดใช้จริงกับข้อจำกัด/นโยบาย AI เป็นคำถามรอบแรกที่ส่งแล้ว

หลังตอบจึงสรุปโครงสร้างและบทเดโมร่วมกัน ก่อน wireframe SVG และการสร้างเว็บ ไม่มีการสร้างภาพในขั้นวิเคราะห์นี้
